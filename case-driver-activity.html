Case study, VZone at Gnapi Technologies

Showing a fleet what each driver did, when only vehicles report in.

A report I delivered end to end across five services, from a Flink job to a reusable React grid.

My role
End to end, pipeline to screen
Stack
Flink (Java), ClickHouse, NestJS, React
Backfill
About 63,000 segments

The problem

VZone tracks about 10,000 vehicles, and every GPS event says which vehicle moved. It never says who was driving. Drivers switch vehicles, and one vehicle can have several drivers in a day.

Fleet operators wanted a report about people: what each driver did over a period. That means matching every stretch of activity to the driver who was assigned to that vehicle at that moment.

What I built

  • A Flink job that attributes activity to drivers using temporal joins, so a segment is matched to the assignment that was valid at the time it happened.
  • A ClickHouse table to hold the attributed segments for reporting.
  • NestJS APIs that serve the report to the web app.
  • A reusable React grid that shows it to operators, built so other reports can use the same component.
  • A backfill of about 63,000 existing segments.

The work crossed five services, and I carried it through all of them.

Making it fast

The report query ran one ClickHouse query per time window, so a single report could mean hundreds of database round trips.

I replaced the per-window queries with one batched query and used partition pruning, so ClickHouse only reads the partitions the report needs. One report now takes one round trip.

The outcome

  • Operators can see activity per driver, not only per vehicle.
  • Hundreds of database round trips per report became one.
  • The grid component is reusable for other reports.
